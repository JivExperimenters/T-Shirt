# Peer feedback and decision log

Use GitHub Issues to document research feedback and the decision made for each suggestion. Do not create fictitious issue numbers or claim that a reviewer has approved a change.

## Current research-round requirement

File **3–5 constructive GitHub issues per classmate, per project**. Each issue should include:

1. A specific observation, gap, or question.
2. Why it matters to the research or design decision.
3. A useful next step and a relevant page, source, or example.

## Decision history

For each incoming issue, decide whether to **implement**, **investigate**, **defer**, or **decline** the suggestion and explain why in the issue discussion.

For accepted feedback, show the full chain:

**Peer issue → decision → linked commit or pull request → verification → resolution**

- Reference the issue number in a related commit or pull request.
- Link the change in the issue and state how it was checked.
- Keep unfinished work open with a specific next step.
- Explain declined suggestions rather than silently closing them.
- Ask the reviewer to retry a resolved issue before closing it.

## Privacy

Keep private reflections and personal eligibility circumstances in Canvas, not in this public repository or public GitHub issues.
